# TermDock

TermDock 是 Windows 10/11 x64 桌面终端，支持本机 Shell、SSH、串口和嵌入式 Linux 循环重启测试。每个标签页有独立的终端回滚、连接和日志。

## 启动

将 `TermDock-V0.0.4_1119-win-x64.zip` 完整解压，再打开其中的 `TermDock\TermDock.exe`。同目录的文件需要一起保留。发行包未经代码签名。需要核对下载时，可运行 `Get-FileHash .\TermDock-V0.0.4_1119-win-x64.zip -Algorithm SHA256` 并和同名 `.sha256` 文件比较。

需要固定到任务栏时，把程序解压到长期保留的位置，例如 `D:\Tools\TermDock`，再双击其中的 `Create-Start-Menu-Shortcut.cmd`。它为当前 Windows 用户创建开始菜单快捷方式，目标和图标都指向该目录中的 `TermDock.exe`。从开始菜单启动后可固定到任务栏。遇到旧版白色固定项，取消固定后重新固定一次；以后升级时替换同一目录中的程序文件。

便携包使用系统的 Microsoft Edge WebView2 Runtime、.NET Framework 4.8 和 `tar.exe`。Windows 11 自带 WebView2。缺少 WebView2 的 Windows 10 会提示打开微软下载页。随包携带的 Node.js 在首次启动时解压到 `%LOCALAPPDATA%\TermDock\runtime`，占用约 77 MB，之后会复用。系统已有这些组件时可以离线启动。

默认日志根目录为 `%APPDATA%\TermDock\logs`，侧栏的 **日志目录** 可以打开它。程序默认尝试使用 xterm.js 的 WebGL 渲染器，状态栏显示当前使用的渲染方式。WebGL 初始化失败或上下文丢失时，终端切换到 DOM 渲染。字体、字号、回滚行数和 GPU 开关在 **设置 → 终端** 中。

新配置默认使用 **macOS 风格** 等宽字体和行距。Windows 上未安装 SF Mono 或 Menlo 时，程序使用随包附带的 IBM Plex Mono。已有配置可以在 **设置 → 终端 → 字体** 中切换。

可以同时打开多个本机 PowerShell、串口和 SSH 标签页。把顶部标签拖到另一个标签上即可交换位置。按 `Alt+1` 至 `Alt+9` 切换当前从左到右的第 1 至第 9 个标签。

点击顶部标签栏左端的按钮，可收起或展开会话栏。收起时终端使用腾出的宽度，连接保持在线。

标签、当前连接地址和工具按钮共用一行。悬停图标可查看操作名，长标签和地址悬停可查看全文。窄窗口会缩短地址和标签，并将部分工具移入 **更多**；所有操作也能在 **更多** 中找到。标签较多时可用鼠标滚轮横向切换，或用 Alt 快捷键。

工具栏的连接按钮跟随活动窗格。在线时点击 **断开**，完成断开后同一位置显示 **连接**。本机 Shell 按原设置重新启动。SSH 和串口会打开已填写当前会话参数的连接窗口，确认后连接。SSH 可直接使用已保存的密码。

打开至少两个标签后，点击 **左右分屏** 或 **上下分屏** 图标，按位置选择两个连接。分屏时可从窗格右上角的小下拉框更换会话，拖动分隔线调整大小。点击顶部 **×（取消分屏）** 让当前活动窗格占满终端区域。其他会话仍可从原标签切回，继续使用原连接和回滚记录。**更多 → 交换窗格 / 关闭分屏** 也可操作布局。点击窗格后，细橙色边框标明当前活动窗格，顶部工具和底部命令均跟随它。

## 最近连接与升级

成功连接的串口和 SSH 会自动出现在侧栏的 **最近连接**。相同 COM 口或相同 SSH 主机、端口及用户名保留最近一次成功连接的参数。右键可编辑最近记录、保存成新会话。当前标签和最近记录也可拖入 **已保存会话** 或具体分组，填写并确认后保存。已保存项的 **设置 / 重命名** 更新原项，**另存为新会话** 则创建副本。

编辑串口或 SSH 会话时可设置分组、收藏及逗号分隔的高亮关键词。侧栏可展开分组，并按名称、分组或连接地址搜索。关键词高亮应用到终端显示。

配置保存在当前 Windows 用户的 `%APPDATA%\TermDock` 下。

| 文件 | 内容 |
| --- | --- |
| `sessions.json` | 已保存的会话和最近连接 |
| `command-buttons.json` | 命令按钮及分组 |
| `settings.json` | 终端偏好、已确认的 SSH 主机密钥、AI 模型列表和 ADB 路径 |
| `credentials\*.dpapi` | 当前 Windows 用户保护的 SSH 密码和 AI Key；SSH 密码按主机、端口和用户名匹配 |

首次运行新版时，旧版 `settings.json` 里的已保存会话和命令按钮会自动迁移。升级时关闭 TermDock，再替换解压出的程序目录。只要保留 `%APPDATA%\TermDock` 下的配置，重新启动即可继续使用原来的会话、最近连接和按钮。需要备份或迁移到另一台电脑时，可在关闭程序后复制这三个文件，并在目标 Windows 用户的同一路径下还原。

## 命令按钮栏

1. 点击底部状态栏上方的 **管理按钮**，新建分组并填写分组名称。
2. 点击 **添加按钮**，填写按钮名称、发送命令和行尾。默认发送 CR，也可选择 LF、CRLF 或无行尾。点 **保存** 后配置会保留在本机。
3. 用底部下拉菜单切换分组，点击图标文字按钮即可将命令发给最后活动的终端。悬停可查看完整名称和发送内容。整栏保持一行，放不下的完整按钮按原顺序放入最右侧 **»**，向上展开后可直接发送，随后恢复终端焦点。

要修改或删除按钮、删除分组，可重新打开 **管理按钮** 并保存。

## 本机 Shell

从左侧 **本机 Shell** 分组启动 Windows PowerShell、CMD、已安装的 PowerShell 7 或 WSL。**自定义启动…** 可以指定绝对工作目录和逐行填写的 `NAME=value` 环境变量。将资源管理器中的文件拖入 PowerShell 或 CMD 会在光标处插入原始绝对路径。多个路径按拖入顺序以空格分隔。可以编辑输入并按需自行添加 Shell 所需的引号，再按 Enter 执行。窗口尺寸通过 ConPTY 同步，退出状态显示在底部。[ConPTY 系统要求](https://learn.microsoft.com/en-us/windows/console/createpseudoconsole)

## ADB

TermDock 随包提供 ADB `1.0.41`，默认安装到 `%LOCALAPPDATA%\TermDock\tools\adb`。新开的 Windows PowerShell 和 PowerShell 7 会优先从配置的目录查找 `adb`。可用 `Get-Command adb` 和 `adb version` 核对位置和版本。

在 **设置 → ADB** 选择工具目录，点击 **保存** 安装到指定位置。新开 PowerShell 后，点击终端右上角 **ADB** 或 **更多 → ADB 命令**，即可在当前光标处填入 `adb `。例如补上 `version` 后按 Enter 检查版本。列设备和拉取文件可在同一处补全 `adb devices -l` 和 `adb -s <设备序列号> pull <设备端路径> <本地目录>`。[ADB 设备和文件传输](https://developer.android.com/tools/adb)

## SSH

1. 点击侧栏的 **SSH**，输入主机、端口和用户名。选择密码、私钥，或选择 **SSH Agent** 以使用 `SSH_AUTH_SOCK` 或 Windows OpenSSH Agent。
2. 首次连接时，向管理员核对显示的 SHA256 主机密钥指纹，再点击 **信任并连接**。之后如果指纹不同，TermDock 会在认证前中止连接。确认服务端确实换钥后，关闭 TermDock，备份 `settings.json`，删除 `hosts` 中对应的 `[主机名或 IP]:端口` 条目，再重新连接并核对新指纹。
3. 登录或编辑会话时，填写密码并勾选 **记住密码** 可用 Windows DPAPI 保存密码，写入并验证可读取后才提示已保存。重新打开会话设置可查看保存状态和掩码，点击 **显示** 查看实值。密码框留空会使用对应目标的已保存密码，输入新密码并勾选可替换，也可选择 **清除这个目标的已保存密码**。改变会话名称时继续使用原凭据，修改主机、端口或用户名时按新目标匹配。私钥口令仅用于当次连接。
4. SSH 分配 `xterm-256color` PTY，最大化、还原、分屏和调整 AI 栏时同步行列。直接使用方向键、Tab、`Ctrl+C`、`Ctrl+D` 和 tmux 的 `Ctrl+B`。使用 `Ctrl+Shift+C` 复制选区，`Ctrl+Shift+V` 粘贴，`Ctrl+Shift+F` 搜索回滚。终端支持应用鼠标模式、UTF-8、ANSI 256 色及备用屏幕。
5. 鼠标划选非空文字会自动复制；应用启用终端鼠标上报时，按住 Shift 划选。右键粘贴到点中的终端，输入框右键打开编辑菜单。密码框不自动复制。日志只记录收到的终端输出，SSH 认证凭据由连接对话框提交。
6. 登录后可打开 **SFTP** 浏览远程目录和上传或下载单个文件。目标路径已有同名文件时传输失败。
7. **端口转发** 在本机 `127.0.0.1` 创建监听端口，目标主机和端口由 SSH 服务器访问。本地端口可填 `0` 让系统分配。点击 **停止转发** 或断开 SSH 即可释放监听端口。

## AI 对话与自动操作串口

在 **设置 → AI** 输入 API Key，并从 **模型全名** 下拉框选择 `GLM-5.3-Flash-NVFP4` 或 `DeepSeek-V4.1-Flash-1017`，点击 **保存**。Key 使用 Windows DPAPI。保存后设置页和对话栏均显示掩码，点击 **显示** 可核对。只改模型、Key 留空会沿用原 Key。可填写新 Key 替换，或点击 **清除 API Key**。点击 **新增模型 → 添加并选择** 可保存自定义全名，重启后仍可选择。

接口固定为 `https://llm.amlogic.com/v1/chat/completions`，使用 Bearer 认证。**测试连接** 发送 `Reply with OK only.`、`max_tokens: 500`。需要能访问该内网服务及有权限的 Key，错误会区分认证、模型、网络、超时、空响应和上下文长度。配置、日志及程序包不保存明文 Key；换电脑或 Windows 用户后需重新填写凭据。

1. 点击顶部 **AI 助手** 或 **更多 → AI 助手** 打开同一个对话。点击 **停靠** 放到右侧，拖动分隔线调整宽度，点击 **弹出** 恢复非模态对话框。首次默认勾选当前 SSH 或串口，也可选择后台标签。
2. 输入问题后点击 **发送** 或按 `Enter`，按 `Alt+Enter` 换行。每次发送读取选中的终端画面，持续串口输出或未提交的命令半行也可正常问答。对话显示读取、请求、接收回复和耗时。如果接口提供流式推理信号和正文，会依次显示思考阶段并逐段呈现正文。输入区的 **思考** 按当前消息设定跟随默认、快速、标准或深度。同一轮自动操作沿用发送时的挡位。
3. 选择 **自动操作串口**，填写任务后点 **发送并执行**。可以预选目标，也可以从待答卡片选择实际已连接的 COM 口。写入确认卡列出目标、任务和本次授权的操作。点击 **允许本次** 才会执行，点击 **不允许** 或关闭卡片会结束本轮。卡片还支持单选、多选和填写参数，提交后原任务继续。
4. 每轮最多 **6 个动作**，总时长最多 3 分钟。TermDock 支持等待指定提示符、延时、发送和读取新回显。启动写入前如有未完成的手动输入，会提示先按 `Enter` 完成或按 `Ctrl+C` 取消，然后重新发起。等待提示符超时会跳过后续操作。点击 **停止**、手动接管、关闭对话框、断开或日志失败都会停止后续写入。串口定时任务与 AI 自动操作互斥。
5. **读取并分析** 使用所选终端的当前画面。需要分析一段日志时，先在 SSH 或串口终端划选文本，再在 AI 对话里点击 **分析选区**。这两种分析只读取内容。选区分析后的追问沿用该选区，点击 **改用所选终端当前画面** 可恢复实时上下文。**新对话** 清空本次聊天并回到仅对话模式。

终端输出不会自行触发 AI 请求，只有发送问题或点击分析时才提交。自动操作使用受校验的单步动作，普通回复文字不会当作命令发送；如果模型不能返回有效动作，本步停止。AI 对话和命令执行记录保留在当前应用进程内，退出后不保存；串口原始日志照常记录，事件日志额外记录 AI 轮次、写入字节数和状态。自动操作模式及目标不跨重启保存。

## 串口与循环重启

1. 安装 USB 转串口设备所需的 Windows 驱动。点击 **串口**，使用 **刷新** 更新 COM 列表，在 COM 输入框选择或键入端口号。默认串口参数为 **921600 / 8N1 / XON/XOFF**。硬件流控可选择 RTS/CTS。可设置终端发送的行尾及本地回显，连接后可通过工具栏发送约 250 毫秒的 **Break**。
2. 连接后，在终端确认串口能正常收发，按需登录 Linux。打开 **定时发送**，填写命令、间隔、行尾及可选最大轮数。默认发送 `reboot`，间隔 60 秒，行尾为 CR。
3. 保持 **等待 Linux shell 提示符** 勾选。留空时识别独立的 `#`、`/ #`、`$` 和 `root@board:~#` 一类提示符。自定义提示符按去除首尾空白后的整行文字匹配。如果板卡的启动程序也显示类似 `#` 的提示，使用能区分 Linux shell 的专用提示符。识别需要当前提示符行保持约 400 毫秒安静。静默板卡可按回车刷新提示符。
4. 点击 **开始**。首次在完整间隔之后尝试发送。每轮串口写入完成后重新计时。倒计时结束时，如果还在引导程序、登录提示、恢复过程中或手动输入中，任务等到 shell 就绪后只发一条。关闭提示符等待会允许在未识别出 shell 时发送，仍会等待已识别的引导程序、登录提示和未完成的手动输入。
5. **已发送轮数** 在驱动完成写入后更新。最近一轮看到 BL2、U-Boot 或 kernel 启动行时显示 **已看到**。收到新的稳定提示符后增加 **已恢复轮数**。点击 **停止** 后保留串口连接和最后一轮日志，已经交给串口的字节可能仍在发送。串口断开或磁盘写入失败时任务停止，重连后需手动开始。

选择 **多步流程** 可添加命令、等待、自动登录并调整顺序。等待最短 1 ms，事件日志分别记录设定等待、实际等待和相邻写入的间隔。可以立即运行一次，也可以按原有规则等待首轮并重复执行。自动登录默认关闭；开启后填写用户名、密码、提示和超时。它识别当轮新收到的提示，密码写入后需看到新的 Shell 提示才继续，失败或超时后停止。密码只用于本次任务，设备回显的相同密码字节会被遮蔽。手动输入会停止进行中的多步流程。面板可从右边收起或展开，任务照常运行。

### 日志

连接串口前，在连接或会话编辑窗口的 **串口日志** 区域设置 **保存位置** 和 **日志格式**。点击 **浏览** 选择目录，点击 **默认** 恢复到 `%APPDATA%\TermDock\logs`。点击 **保存** 可以把设置用于这个会话的后续连接。每次连接创建独立子目录，终端工具栏的 **日志** 可直接打开它。

串口默认使用 **每行加毫秒时间戳**，例如 `[2026_11_11 14:30:00.123] Linux started`。时间使用电脑的本地时间，取该行首字节到达 TermDock 的时间。这种模式同时生成 `.raw` 文件。选用 **原始日志（无时间戳）** 时，`.log` 本身保存接收字节。连接时自动开始会话记录；**停止记录** 会刷盘并关闭当前分段，**开始记录** 会创建新文件。分轮记录仍独立运行。

| 文件 | 内容 |
| --- | --- |
| `COM12-20261117_153045.log` | 手动控制的会话分段，同一秒重开会添加数字后缀。本机 Shell 和 SSH 仍使用 `session.log`。 |
| `reboot_0001_20261111_143000.log` | 开始写入这一轮命令前切换到该文件，之后收到的字节写到下一轮开始或连接断开。停止定时任务后最后一个文件继续追加。文件序号在同一连接内递增。 |
| `COM12-*.raw`、`reboot_*.raw`、`workflow_*.raw` | 带时间戳模式下并行保存的会话分段和分轮字节。 |
| `events.log` | 带时区偏移的本地时间、启动/等待/停止、写入结果、启动标记、恢复和异常。 |

回滚行数仅限制终端显示。磁盘日志直接接收后台输入。持续突发流量超过显示队列处理能力时，终端会提示跳过的字节数，可从磁盘日志查看完整输出。

## 从源码运行与打包

在 Windows x64 上安装 Node.js 22.12 或更新版本及 npm，从项目根目录运行以下命令。开发版 `npm start` 使用 Electron。打包脚本使用 Windows 自带的 .NET Framework 编译器及 `tar.exe`，并从 npm、NuGet 和 Node.js 源码仓库下载并校验锁定版本的构建依赖。

```powershell
npm ci
npm start
npm run package:win
npm run package:source
```

产物为 `release\TermDock-V0.0.4_1119-win-x64.zip`、`release\TermDock-V0.0.4_1119-source.zip` 和各自的 `.sha256`。内置 ADB 后，便携 ZIP 的大小上限为 22,000,000 字节。Windows 宿主位于 `src\windows`，两个宿主共用 `src\main` 的连接、日志和定时代码，以及 `src\renderer` 的 xterm.js 界面。
