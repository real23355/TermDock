# TermDock V0.0.3_1118 · 2026-11-18

基于 V0.0.2_1117 增量更新，按 `TermDock-20261118-refinement-requirements.md` 的功能需求实施。现有 WebView2 / xterm.js / ConPTY / ssh2 / SerialPort 底座继续使用。旧版 ZIP 保留，配置、SSH 凭据关联和日志目录兼容，没有迁移或清空用户数据。本文件记录布局与凭据阶段的定位和测试；最终发行同时包含 AI 对话及自动串口操作，见根目录 ACCEPTANCE-0.0.3.md。

## 密码故障的实际定位

在保留的 0.0.2 Windows 便携版中复现：打开 SSH 对话框，主机填 `EXAMPLE.invalid`，输入测试密码并勾选“记住密码”，然后仅把主机改成等价的 `example.invalid`。结果为密码长度 0、记住密码 false。原因是 host / port / username 的每次 input 都无条件清空认证输入和勾选状态，之后“保存”仍会成功保存不含凭据的会话。这是本次确认的具体触发条件，不能据此断言用户此前所有失败都由它引起。

另在后台发现，0.0.2 的“连接并记住密码”在 connected 事件中调用未等待的 `void credentials.save()`，也没有后台成功确认。未复现到退出时丢失文件，但代码存在退出与写入竞争的风险。

修改后的链路是：

1. 界面按规范化后的主机（忽略大小写及首尾空格）、端口和账号比较目标；等价编辑保留密码及勾选。真正更改目标时清除输入并明确提示，保留“记住密码”的意图。
2. 勾选记住却没有输入或可用存储凭据时，阻止静默保存。重命名不会改变凭据目标。
3. IPC 校验后调用当前 Windows 用户的 DPAPI，临时文件写入并 flush，读取并验证能解密后原子替换原文件；同一凭据的保存和清除按顺序执行，退出等待保存完成。
4. “保存”或“连接并记住密码”等待后台完成后才显示已保存。读取时验证可解密；损坏、用户不匹配或目录不可写时显示安全的原因，普通配置及诊断不返回明文密码。

实际便携版已验证：输入、勾选和等价目标编辑 → IPC → DPAPI 写入 → 替换密码 → 完全退出 → 同用户重开 → 留空密码连接成功 → 清除凭据。旧版 `.dpapi` 文件名和 SSH 目标哈希规则保持兼容。

## 功能变化

- 顶部侧栏开关、标签、当前连接信息和工具共用 32 px 单行。移除独立分屏行和每个终端的地址 / 操作行。搜索、日志、记录、断开、SFTP、端口转发、重连、Break、任务面板和分屏操作均可从“更多”访问。操作跟随活动窗格；活动窗格显示橙色细边框。
- 长地址和标签省略并提供完整提示；标签可横向滚动或 Alt+1…9 切换。窄窗口先收紧地址和标签，再隐藏部分图标至“更多”。
- 底部 28 px 命令栏和 20 px 状态栏，命令按钮为统一图标加文字。溢出按钮“»”向上展开，按钮完整显示、无换行或横向滚动，按原顺序各归一处。窗口、DPI、分组及侧栏变化会重新计算。
- 设置新增 AI 分类，仅配置掩码 Key 和可编辑的模型全名。默认 GLM-5.3-Flash-NVFP4，预设 DeepSeek-V4.1-Flash-1017。固定 `https://llm.amlogic.com/v1/chat/completions`、Bearer 和 Chat Completions 格式；模型普通配置保存，Key 用 Windows DPAPI。
- AI 右栏支持多个 SSH / 串口当前视口（包括后台标签和当前回滚位置）、当次选区、来源及同批时间标注、追问、替换上下文、复制、取消和收起保留对话。勾选不会发请求。重新读取会替换推理所用上下文，旧会话文字不会混入新范围。
- 模型回复按纯文本显示；原始串口日志、渲染及 AI 上下文独立。网络请求在后台执行，终端可继续使用；未提供 Key 时阻止请求，错误不透传服务正文或认证头。

## 逐项人工验收与尚未完成的实测

1. **布局 / DPI：** 在 Windows 显示设置中实际切换 100%、125%、150%，重开程序；打开 SSH、COM3、COM12 和多个标签，拉窄并收起侧栏。检查 32 px 单行、完整图标、地址提示和“更多”中的全部操作。打开两种分屏，点不同终端后使用顶部搜索 / 日志 / 断开。
2. **命令栏：** 创建至少 12 个不同长度的命令，缩窄使其进入“»”，向上展开逐项核对顺序、唯一性和实际发送目标；拉宽恢复，切组和侧栏开关后复核；发送后直接逐键输入。
3. **SSH 密码：** 填写正确密码并勾选记住，改变主机名大小写或首尾空格再保存，检查已保存提示。断开重连后完全退出并重开，用空密码框认证。改真实目标时应明确要求重填，清除后退出重开应无保存状态。普通配置和日志不应出现密码。
4. **本地 / tmux：** 在实际便携终端逐键输入 `echo termdock-ok`，用中文 IME 候选转换，补全及方向键。执行 `Start-Sleep -Seconds 30` 用 Ctrl+C 中断。SSH / WSL 内运行 `tmux new -As termdock-verify`，用 Ctrl+B % / o / d，重连附着，运行 vim / top 并缩放窗口，切换标签和分屏后重复输入。
5. **真实 GLM（尚未提供 Key / 内网调用）：** 设置 → AI 选择 GLM-5.3-Flash-NVFP4 并保存有效 Key，测试应显示 OK。切预设及手输完整模型名，留空 Key 保存并重启。更换 Key、清除并重启。用无效 Key、不可用模型、断开内网分别核对错误；操作系统 / 企业代理及 TLS 证书环境也需在真实内网确认。
6. **AI 日志：** 在 SSH A、串口 B、后台 C 分别输出不同标记，只勾选 A / C 后读取，确认回复关联到正确来源且 B 未提交；划选 B 的一段从“更多”分析，追问后改变来源重读，核对新输出。关闭勾选来源、全部清屏、取消和收起后重开逐项复核。
7. **PL2303（本机未接入）：** 选实际 COM 口、921600 / 8N1 / XON/XOFF，硬件流控关闭；执行至少两轮、一次超过 60 秒启动、一次停在 login，检查分轮开头及原始日志。停止后继续接收最后一轮；拔线、日志不可写时任务应停，重连手动恢复。断开后立即用烧录工具打开同一 COM 口。真实软件流控、物理收发、长时间异常记录及 Windows 10 真机仍待实测。

这版未取得真实内网模型分析结果，也未用模拟串口替代 PL2303 实板验收。现有配置和历史日志继续保留。
